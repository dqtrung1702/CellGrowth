01 / Business Overview

Business Overview

Internal IAM Data Access Approval RBAC + Data Scope

Ở mức nghiệp vụ, UAA đang giải quyết ba vấn đề cùng lúc: xác thực người dùng, cấp quyền thao tác trên ứng dụng và quản lý phạm vi dữ liệu mà người dùng được nhìn thấy. Điểm khác biệt quan trọng là quyền dữ liệu không được lưu như một bảng tách biệt hoàn toàn; thay vào đó Permission là hạt nhân chung, rồi mở rộng sang UrlPermission, PagePermission và DataPermission.

Identity
Người dùng, đăng nhập, MFA, social identity

Gồm User, UserIdentity, UserTOTP và SocialProvider.

Authorization
Role, permission, URL/page access

Gồm Role, Permission, UserRole, RolePermission, UrlPermission, PagePermission.

Data Scope
Data set, set, data permission

Set nhóm dịch vụ và dataset; DataPermission gắn permission với set dữ liệu.

Approval Layer
Access Request là lớp workflow trung gian
  • Người dùng không nhất thiết được cấp role hoặc data scope trực tiếp.
  • AccessRequest lưu yêu cầu, AccessRequestItem lưu từng hạng mục, AccessRequestLog lưu lịch sử duyệt.
  • Approval service sau đó áp role hoặc data permission vào user thực tế.
Technical Pattern
Controller + Schema + Service + ORM
  • Controller nhận request và validate body bằng Pydantic schema.
  • Service xử lý nghiệp vụ, query repository và sinh ResponseEnvelope.
  • Route cũ thiên RPC như /getRoleList; route mới thiên REST như /access_requests.
Điểm business cần nhớ Một user có thể mang đồng thời quyền từ role và một data_permission_id trực tiếp. Điều này cho thấy nền tảng đang hỗ trợ cả mô hình cấp quyền theo bundle lẫn cấp quyền dữ liệu trực tiếp cho cá nhân.
02 / Core Entity Relationship

Core Entity Relationship

Identity / Workflow Authorization Data Scope Catalog / Config

Sơ đồ được tách thành ba góc nhìn để tránh các đường chéo dài cắt qua toàn bộ canvas. Hình đầu chỉ giữ backbone quan hệ dữ liệu, hình thứ hai cô lập workflow duyệt quyền, và hình thứ ba dành riêng cho identity/MFA.

Overview Relationship View
Authorization backbone + data scope catalog

Chỉ giữ các FK cốt lõi. Tất cả connector đều đi ngang hoặc dọc để người đọc lần theo từng lane.

Approval Relationship View
Workflow lane tách riêng để không cắt sang backbone

AccessRequestItem được nối thẳng tới các target grant bằng nét đứt theo từng nhánh nghiệp vụ.

Identity Relationship View
User, MFA và social login

Giữ User ở trung tâm, tách rõ phần one-to-many với identity và one-to-one với TOTP.

Structural Insight
Permission vẫn là hub, nhưng không còn chiếm toàn bộ canvas

Khi tách phần approval khỏi backbone, người đọc có thể hiểu quan hệ FK thật trước, rồi mới xem các link nghiệp vụ được duyệt qua AccessRequestItem.

Reading Rule
Nét liền là FK trực tiếp, nét đứt là liên kết áp dụng nghiệp vụ

Quy ước này giúp phân biệt rõ quan hệ tồn tại trong schema DB với quan hệ chỉ xuất hiện khi service suy diễn hoặc apply quyền.

  • Models: AccessRequest, AccessRequestItem, AccessRequestLog.
  • Schemas: access request create, approve, reject, list.
  • Domain này nối giữa identity, role và data permission ở tầng business process.

04 / Key Flows

Key Business Flows

Flow 1
Login + MFA
  • LoginRequest vào /login.
  • AuthService xác thực User; nếu cần MFA thì trả mfa_token.
  • /mfa/totp/verify_login xác minh OTP và phát JWT cuối cùng.
Flow 2
Role / Permission Administration
  • Admin tạo Permission kèm URL list hoặc DataSets.
  • Admin tạo Role và gắn permission qua RolePermission.
  • Admin gắn role cho user qua UpdateUserRoleRequest và bảng UserRole.
Flow 3
Access Request Approval
  • User gửi AccessRequestCreate với role hoặc data permission mong muốn.
  • Hệ thống tạo AccessRequest + AccessRequestItem.
  • Approver duyệt hoặc từ chối; service ghi AccessRequestLog và áp grant thực tế.
Flow Entry Points Main Schemas Main Models
Authentication /login, /check_auth_ext, /mfa/totp/* LoginRequest, VerifyTOTPRequest, ResponseEnvelope User, UserTOTP, UserIdentity, SocialProvider
Authorization Provisioning /addRole, /updateRole, /addPermission, /updateUserRole AddRoleRequest, AddPermissionRequest, UpdateUserRoleRequest Role, Permission, RolePermission, UserRole
Data Scope Catalog /addSet, /updateDatasetBySet, /getDataSetByUser AddSetRequest, UpdateDatasetBySetRequest, DataSetByUserRequest Set, Dataset, DataPermission, Permission
Approval Workflow /access_requests, /access_requests/<id>/approve, /access_requests/<id>/reject AccessRequestCreate, AccessRequestApprove, AccessRequestReject, AccessRequestListQuery AccessRequest, AccessRequestItem, AccessRequestLog, User

FK: role_id -> roles.id FK: permission_id -> permissions.id

Bảng nối user với role, đại diện grant RBAC trực tiếp lên cá nhân.

FK: user_id -> users.id FK: role_id -> roles.id
UrlPermissionuaa.url_permissions

Danh sách route/method được gắn vào một permission. Đây là lớp kỹ thuật để middleware quyết định quyền truy cập endpoint.

Fields: permission_id, url, method, type
PagePermissionuaa.page_permissions

Danh sách page UI được gắn vào permission; phục vụ menu/page visibility ở frontend.

Fields: permission_id, page
Setuaa.sets

Nhóm dữ liệu ở mức business catalog. Một set thường đại diện một dịch vụ hoặc một phạm vi nghiệp vụ cụ thể.

Fields: setname, services, setcode Relationships: DataPermission[], Dataset[]
DataPermissionuaa.data_permissions

Nối một permission kiểu DATA với một set dữ liệu. Đây là cầu nối giữa catalog dữ liệu và engine permission.

FK: permission_id -> permissions.id FK: set_id -> sets.id
Datasetuaa.datasets

Hạt dữ liệu nhỏ nhất được mô tả trong catalog. Bộ ba tablename, colname, colval cho thấy filter scope đang được mô hình hóa ở mức cột.

FK: set_id -> sets.id Fields: tablename, colname, colval
AccessRequestuaa.access_requests

Header record của quy trình xin quyền. Lưu requester, loại request, trạng thái, thời hạn và kết quả apply.

Fields: requester_id, request_type, status, reason, ttl_hours, approved_at, rejected_reason Relationships: requester_user, items[], logs[]
AccessRequestItemuaa.access_request_items

Chi tiết grant cần duyệt. Có thể tham chiếu role, permission dữ liệu và set trong cùng một item.

Fields: request_id, role_id, data_permission_id, set_id, note
AccessRequestLoguaa.access_request_logs

Audit trail cho hành động create, approve, reject, cancel.

Fields: request_id, actor_id, action, note, created_at
UserIdentityuaa.user_identities

Liên kết user nội bộ với external identity provider như Google hoặc provider khác. Lưu external id, email, display name, avatar và tokens JSON.

Fields: provider, external_id, email, display_name, avatar_url, tokens_json
UserTOTPuaa.user_totp

Thiết lập MFA TOTP một-một với user. Khóa chính là user_id.

Fields: user_id, secret_base32, confirmed, backup_codes_json
SocialProvideruaa.social_providers

Cấu hình provider social login ở mức hệ thống, gồm client id/secret, redirect URI, scopes và cờ enabled.

Fields: provider, client_id, client_secret_enc, redirect_uri, scopes, enabled, updated_by
